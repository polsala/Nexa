# ADR-003 — Univer integration boundary

Status: accepted, with a documented adaptation.

Investigated stable Univer OSS 0.25.1; do not adopt 1.0 release candidates. Sheets uses OSS canvas rendering, formulas, undo, filtering, sorting, validation, conditional formatting and find/replace. Only packages/sheets imports its APIs. The local bootstrap registers individually selected presets; the convenience @univerjs/presets umbrella was rejected after a dependency audit showed that it also installs proprietary Pro packages.

The current [Slides installation](https://docs.univer.ai/guides/slides/getting-started/installation) requires Pro licensing. The [Docs installation](https://docs.univer.ai/guides/docs/getting-started/installation) and package investigation did not establish a complete stable OSS table-editing route meeting this product's accessibility and clipboard needs. We therefore use MIT Tiptap/ProseMirror for Writer and inline slide text, and a small owned SVG geometry engine for Slides. This provides actual editable tables and static presentations without a server or license dependency.

All adapters implement EditorEngine. A future engine replacement must pass native-format round-trip and UI workflow tests. There is no required Pro package, license server or online import/export. The engine adapters may evolve independently from the native schema.

Native WebKit testing exposed delayed `DocSelectionRenderService.focus()` calls from cell-editor initialization after a tab had become inert. Disabling shortcuts and clearing the focused unit did not stop these lower-level calls; on WebKit they could blur the active Writer/Slides input even when the hidden input could not receive focus. The version-pinned patch in `patches/@univerjs__docs-ui@0.25.1.patch` gates only that service's focus method on a connected, non-inert host outside other modal dialogs. It changes neither document data nor formula semantics, and retains the upstream Apache-2.0 notice. Revalidate/remove it when upgrading Univer. Both ESM and CommonJS entries are patched through pnpm, never by editing an installed dependency ad hoc.

The optional `EditorEngine.prepareSnapshot()` boundary commits an active input before explicit save/export/print/close. Sheets uses Univer's [documented asynchronous end-editing API](https://docs.univer.ai/guides/sheets/features/core/range-selection); reading the workbook snapshot alone is insufficient while a cell is still being edited. Background recovery snapshots do not forcibly terminate a cell edit.

`SheetEditChanging` / `SheetEditEnded` Facade events track a single engine-independent draft without per-keystroke workbook copies. `EditorEngine.recoveryDraft()` captures that text separately from committed cells. Recovery restores it literally via the command/undo layer, not as a partially parsed formula; a localized notice explains how to complete it. Nexa's `sheet.cancelInput` action routes Escape to `abortEditingAsync()` while a cell is being edited, avoiding inconsistent Escape handling in the embedded formula controls. Inactive shortcuts do not consume key events. Native package regression tests cover timed persistence and restoration across process restarts.
